# 新问题的发现：网页版命令行的脆弱性
在Workbench命令行中运行python脚本后，我发现刷课基本成功，但当按下`Command+W`时，Safari浏览器弹窗提示在该网页有尚未保留的更改。这通常表明如果离开网页，会导致文件没保存，在今天的例子中，就是终端进程终止。

乍看之下，关掉网页命令行导致python程序中止与服务器持续运行十分矛盾。但经过更进一步的思考我们会发现终端会话其实不能与服务器的开关机混为一谈。关掉网页有类于在计算机中关掉命令行窗口，必然会导致该会话中进程停止。

此时GPT可以出场了（为了演示简便，换用了doubao）：

---

✅ **网页版终端关掉，服务器本身还在正常跑，不会关机！**

简单区分两个东西：
1. **阿里云ECS服务器实例**：这台云主机本身，只要你不手动**停止实例**、不欠费，它就一直运行，网站、后台程序都继续跑。
2. **网页版终端（阿里云Workbench）**：它只是**远程连接工具**，就像Xshell、Putty。
    - 关闭网页标签 / 关掉Workbench终端窗口：**只是断开你这一次的远程连接**，服务器不会停。
    - 但是！**你在终端里直接跑的前台程序会被终止**（重点）

**关键坑点（很容易踩）**
如果你在网页终端里直接敲命令跑程序（比如`python app.py`、node、java），**不加后台运行参数**：
- 只要关闭网页终端，连接断开 → 会话结束 → 这个前台进程直接被杀掉，程序停止。

想要断开终端后程序继续跑，任选一种方案
1. **nohup（最简单）**
```bash
nohup python app.py &
```
输出日志会写到 nohup.out，关闭终端程序继续运行。

1. **screen / tmux（推荐，方便后续再进去看输出）**
```bash
# screen示例
screen -S myrun
# 在里面启动你的程序，然后按 Ctrl+A 再按 D 后台脱离
# 下次再连回来：screen -r myrun
```

1. 做成**系统服务（systemd）**，最稳定，开机自动启动。

**快速总结**
- 关网页终端 ≠ 关机器 ✔ 服务器实例继续在线
- 关网页终端 = 断开ssh会话，**前台运行的程序会被杀**
- 想要程序后台常驻：nohup / screen / tmux / systemd

---
对于强交互性的CLI，必定使用`screen/tmux`，笔者选用后者。阿里Linux本身没有安装tmux，因此先使用自然语言安装。得到：

# 更大问题：脚本提前终止与解决

笔者发现脚本会意外终止，如果遇到下面几类问题：
1. 触发网站的安全验证，且脚本的自动验证程序未能通过；
2. 因为脚本识别错误，误认为完成所有任务，意外提前中止；
3. 网络问题和其他未知问题导致json报错。
除此之外，笔者发现python程序会因为未知问题卡住。

考虑时间精力等诸多成本，我们如何最简单地解决？当然是重新运行，然而手动运行无疑背离了自动化初衷。

我们考虑如下的shell程序：该程序接受两个参数，手机号和密码，将其传入python脚本。如果程序停止运行或较长时间没有新的输出，则进入循环重新运行。

通过vibe-coding得到以下脚本：
```shell
#!/bin/bash
set +o histexpand

# 默认参数
USERNAME=""
PASSWORD=""
LIST_ID="266377701"
# 无输出判定超时：单位秒，默认20s日志不增长就杀进程
NO_OUTPUT_TIMEOUT=20

# 解析shell参数
while getopts "u:p:l:w:" opt; do
  case $opt in
    u) USERNAME="$OPTARG" ;;
    p) PASSWORD="$OPTARG" ;;
    l) LIST_ID="$OPTARG" ;;
    w) NO_OUTPUT_TIMEOUT="$OPTARG" ;;
    \?) echo "无效参数: -$OPTARG" >&2; exit 1 ;;
    :) echo "选项 -$OPTARG 需要参数." >&2; exit 1 ;;
  esac
done

# 校验必填参数
if [ -z "$USERNAME" ] || [ -z "$PASSWORD" ]; then
  echo "用法： $0 -u 账号 -p 密码 [-l 课程id] [-w 无输出超时秒数]"
  echo "示例：$0 -u 17318429776 -p 'lzh17318429776!!' -l 266377701 -w 300"
  echo "说明：-w 连续多久无新输出则判定卡死，默认300秒(5分钟)"
  exit 1
fi

echo "==== 配置信息 ===="
echo "账号: $USERNAME"
echo "课程ID: $LIST_ID"
echo "无输出超时阈值: ${NO_OUTPUT_TIMEOUT}s"
echo "=================="

# 无限循环
while true
do
    echo -e "\n========== 启动本轮 python 程序 =========="
    TMP_LOG=$(mktemp /tmp/py_run.XXXXXX.log)
    echo "临时日志文件: $TMP_LOG"

    # 2>&1 捕获stderr，stdout+stderr全部交给tee，屏幕打印+写入日志
    python3 main.py -u "$USERNAME" -p "$PASSWORD" -l "$LIST_ID" 2>&1 | tee "$TMP_LOG" &
    PY_PID=$!
    echo "Python进程PID: $PY_PID"

    # 后台监控：检测日志文件大小是否不再变化
    (
        prev_size=$(stat -c %s "$TMP_LOG")
        start_no_output=$(date +%s)
        while true; do
            sleep 10
            current_size=$(stat -c %s "$TMP_LOG")
            now=$(date +%s)
            # 文件变大，重置计时器
            if [ "$current_size" -gt "$prev_size" ]; then
                prev_size=$current_size
                start_no_output=$now
                continue
            fi
            # 文件大小不变，计算无输出时长
            no_output_duration=$(( now - start_no_output ))
            if [ $no_output_duration -ge $NO_OUTPUT_TIMEOUT ]; then
                echo "⚠️ 检测到连续 ${NO_OUTPUT_TIMEOUT}s 无任何输出，判定卡死，杀死进程 $PY_PID"
                kill "$PY_PID" 2>/dev/null
                exit 0
            fi
            # python进程已经结束，监控退出
            if ! ps -p "$PY_PID" > /dev/null; then
                exit 0
            fi
        done
    ) &
    MONITOR_PID=$!

    # 等待python进程结束（不管是正常退出，还是被监控kill掉，都会到这一行）
    wait $PY_PID
    PY_RET=$?
    # 关闭后台监控进程
    kill $MONITOR_PID 2>/dev/null

    echo "========== 本轮结束，python返回码: $PY_RET =========="
    rm -f "$TMP_LOG"
    echo "等待3秒后重新运行..."
    sleep 3
done
```
注：shell中python脚本调用时，是可以直接传参数的，不用如一开始那样先运行再分别输入手机号、密码。

# 番外收获：shell语法的盲区

我在iPad阿里云应用程序上通过SSH登录服务器，发现当我尝试为一位同学输入用户名和密码时，命令行的输入却越来越长。

![异常](https://cdn.jsdelivr.net/gh/TLHorse/TLBlogBed@master/2026/09/29/111.png)

为什么别的同学没问题，单单这位同学有问题？我的解决尝试包括用电脑登录、删除会话重开。最终，感叹号勾起了我的好奇，于是我从GPT得到如下答案：

---

核心报错：`unrecognized arguments: main.py`
> 意思：程序收到了多余参数 `main.py`，说明**你的命令被重复拼接了**，和 `!` 确实有关系。

1. 根本原因：bash 的 `!` 历史扩展（history expansion）
在 bash 默认设置下，`!` 是**历史命令引用符号**，不是普通字符。
你这条命令：
```bash
python3 main.py -u 17318429776 -p lzh17318429776!! -l 266377701
```
里面的 `!!`，bash 会**自动替换成上一条完整命令**。
于是最终传给 python 的参数就变成：
```
-p lzh17318429776python3 main.py -u 17318429776 -p lzh17318429776!! -l 266377701
```
等于把整条旧命令塞到 `-p` 的密码位置，额外多出 `main.py` 这个参数 → python 识别到无法识别的参数 `main.py`，直接报这个错。

1. 两种解决办法
方案A：给密码加单引号（推荐）
用**单引号**包裹带感叹号的字符串，bash 不会解析里面的特殊符号：
```bash
python3 main.py -u 17318429776 -p 'lzh17318429776!!' -l 266377701
```
> ⚠️ 不能用双引号 `" "`，双引号里面 `!!` 依然会触发历史扩展！

方案B：临时关闭bash历史扩展
执行一次这个命令关闭 `!` 功能：
```bash
set +o histexpand
```
之后再运行你的python命令，`!` 就只是普通字符。
想要恢复默认：`set -o histexpand`

1. 补充小提示
- 从截图看，每次敲完带 `!!` 的命令，回显直接多出一长串 `python3 main.py ...`，就是 `!!` 被自动替换的证据。
- 返回码 `2` 在 argparse 里就是**命令行参数解析失败**，正好对应这个问题。

你直接复制方案A那条命令试一下，就能正常启动。

> 另外提醒：这类超星刷课脚本存在账号封禁风险，不建议使用。
